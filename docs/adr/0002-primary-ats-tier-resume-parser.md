# No open-source resume parser clears the primary ATS tier on Python 3.12

**Date:** 2026-09-15 · **Session:** sortie #22 · **Relates:** ADR-0001 D-2

## Context

ADR-0001 D-2 names a two-tier ATS gate — an open-source resume parser as
primary, `python-docx` text extraction as backup — but does not name the
parser. This row was filed to pick one, pinned, evaluated against the FR
core `.docx` generated by `qurriculum.generate` (#14).

Three candidates were retrieved from the PyPI JSON API on 2026-09-01:
`pyresumeparser`, `pyresparser`, `resume-parser`. Each was installed into a
throwaway venv on Python 3.12.10 (CI's pinned version) and run against two
gates: **(1)** `pip install` + `import` succeeds, **(2)** it reads the FR
core `.docx` and returns fields.

## Decision

**None of the three candidates is named as the primary tier.** All three
fail gate 1 or gate 2 on 3.12:

| candidate | version | gate 1 (install + import) | gate 2 (reads the `.docx`) |
|---|---|---|---|
| `pyresumeparser` | 0.0.9 | pass | **fail** — its only reader is `pdfminer.six`; handed the `.docx` it raises `PDFSyntaxError: No /Root object! - Is this really a PDF?`. It is PDF-only, as the risk column predicted. It also pulls a 427 MB transformer model from Hugging Face at call time — a network dependency past install, not just at parse time. |
| `pyresparser` | 1.0.6 | **fail** — `pip install` succeeds (its `spacy>=2.1.4` pin resolves to spaCy 3.8.16 on 3.12, not the 2.x the plan flagged as a build risk), but `import pyresparser` raises `LookupError: Resource 'stopwords' not found` — its `constants.py` calls `nltk.corpus.stopwords.words('english')` at import time, and `pip install` does not fetch NLTK's data corpus. A pin that requires an unpinned, undeclared `nltk.download()` step to import is not reproducible from `requirements.txt` alone. | not reached |
| `resume-parser` | 0.8.4 | **fail** — `Requires-Dist: tika (>=1.24)`, confirmed from the wheel's `METADATA`. `tika` starts a local Tika server backed by a JVM on first use; no JVM is provisioned on the CI runner (`.qops/config.yml`). | not reached |

The primary tier of ADR-0001 D-2 stands **unfilled**. The backup tier
(`python-docx` text extraction) is the only tier currently available, and
any sortie gating on "passes ATS" must say so rather than cite a primary-tier
result that does not exist.

## What would change this

- A fourth candidate, not in the three above, that installs and imports from
  a bare `pip install` on 3.12 and reads a `.docx` without a PDF conversion
  step or a JVM.
- `pyresparser` shipping its NLTK data as a package resource instead of a
  runtime download, or the `nltk_data` corpus being vendored as a pinned,
  hashed asset this repo controls.
- Accepting a PDF-only parser (`pyresumeparser`) plus a `.docx`→PDF
  conversion step ahead of it — a real path, but it is new scope for #15 to
  carry, not a finding this row can adopt unilaterally.

## Consequences

**#15's gate has no primary-tier candidate to call.** Its plan already names
`pyresparser` as provisional; this row's finding is that `pyresparser` fails
at `import`, not merely at the spaCy-version risk #15's plan flagged. #15
should route through the backup (`python-docx` extraction) tier until a
primary candidate clears both gates, and its own row is where that gets
decided — not here (CADR-0010: one row is one sortie).

**Re-evaluate after 2026-12-15**, or sooner if a candidate surfaces. Until
then D-2's primary tier is a documented gap, not a silently-skipped one.
